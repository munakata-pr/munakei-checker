# 宗像経済新聞 表記チェッカー（試作）

記者が原稿を貼ると、宗像経済新聞の記者ガイドにある表記ルールに当たる語が光るページです。AI は使わず、正規表現と字数の点検だけで動きます。原稿はページの外に送りません（Content-Security-Policy で通信先を0件にしています）。

- 公開ページ：GitHub Pages（検索エンジンには載せない設定＝noindex）
- 使う人：記者とデスク（「細かい点も表示（デスク向け）」で判断の要る指摘も出す）
- 指摘は3種類：直す（答えが一つ・1クリックで置き換え）／確かめる（文脈で変わる・理由だけ）／形（字数・字下げ・数字・記号など）

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 公開するページ（下の手順で作る。1枚で動く） |
| `template.html` | ページのひな形（画面と操作） |
| `engine.js` | 点検の処理（ブラウザと Node の両方で動く） |
| `build_rules.py` | 記者ガイドの表から `rules.json`・`表記ルール.md`・`index.html` を作る |
| `overrides.tsv` | ガイドの表の行ごとの判定（直す／確かめる／使わない、正規表現、理由） |
| `rules_extra.tsv` | 表の外の規則（ガイド本文の箇条など） |
| `rules.json` | できあがった規則の一覧 |
| `表記ルール.md` | 同じ規則を文章にしたもの（自分の AI に原稿と一緒に渡す用） |
| `sample.txt` | 架空の店のサンプル原稿 |
| `test_engine.mjs` | 点検のテスト |
| `docx_to_json.py` | 本部の返却版 docx を精度テスト用の JSON にする（テスト原稿は公開しない） |
| `DESIGN.md` | 実装で決めたこと |

## ガイドを更新したら

記者ガイドの正本（`munakata-desk/guide/`）が隣のフォルダにある前提です。

```bash
python3 build_rules.py
node test_engine.mjs
```

1. `build_rules.py` が「警告 0件」で終わること
2. `test_engine.mjs` が「失敗 0件」で終わること
3. `index.html` をブラウザで開き、［サンプル原稿］→［置き換えを全部反映］で「直す」が0件になること
4. `git push` で GitHub Pages に反映する

ガイドの表の行を「直す」から「確かめる」に変えたいとき、正規表現を直したいときは `overrides.tsv` の行を書き換えます。

## 公開リポジトリに入れないもの

- 未公開の原稿・本部の返却版（`_test/` に置き、`.gitignore` で除外）
- 本部のコメントの引用（`build_rules.py` が理由の文から消し、残っていれば警告を出す）
- パスワード・ID の類
